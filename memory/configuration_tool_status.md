## 当前进度

已完成：

1. 工程目录导入与导出闭环，104 与 Modbus 按协议分别导出到 `cepiec104`、`cepmodbus`。
2. 模型列表、模型编辑器、设备编辑器基础界面，以及模型/设备双击进入编辑器交互。
3. 模型点位新增、复制、删除，DataRef 实时校验。
4. 104 设备基础字段、点位地址绑定、虚拟点标志勾选导出。
5. Modbus 设备编辑器：
   - 支持 RTU/TCP 参数编辑，串口、波特率、数据位、停止位、校验位均为下拉选项。
   - 支持硬件型号 `myir/talowe`，用于 `RS485_4` 的 `hw_variant` 导出。
   - 支持点位填写寄存器地址、功能码、数据类型、比例、点位类型。
   - 自动生成轮询/写入分组、组内序号和 `dataIndex`。
   - 点位类型以中文下拉展示：遥信、遥测、遥控、遥调。
   - 虚拟点标志改为勾选框，勾选后导出 `self_sig_flag=1`。
6. 从模型创建设备时可选择 104 或 Modbus；Modbus 默认参数为 `RTU / RS485_1 / 9600 / 8 / 1 / N`。
7. Modbus Control 点自动分类规则：`Boolean`、`DBool` 生成遥控，其余 Control 类型生成遥调。
8. 模型导出补齐 service 级字段：`description` 和 `serviceId`。
9. 配置概览页支持删除模型和删除设备；删除模型时会提示并级联删除引用该模型的设备。
10. 导出前会清理对应协议目录下 `model/*.json` 和 `dev/*.json` 旧文件，避免 UI 删除后旧文件残留。
   导入/导出问题统一进入“问题列表”页签，导出警告不再用长弹窗展示；双击问题行会尽量跳转到对应模型、设备或 LogicCenter 编辑页面。
11. LogicCenter 可视化配置已完成阶段 1-8：
   - 支持 `LogicCenter_Config.json` 结构化导入、导出和未知字段保留。
   - 支持 LogicCenter 总览、校验问题展示、AGC/AVC 单虚拟并网点配置。
   - 支持计算点模板生成和计算点列表维护。
   - 支持控制转换编辑器：按源设备/源控制点维护 `control_rules`，目标动作支持 `ctrlcmd`/`data_write`、公式模板、实时值引用插入和表达式展开预览。
   - `CtrlType` 不在控制转换编辑器中展示，也不从配置工具导出；运行态复用北向 `CtrlCmd` 帧中的 `CtrlType`。
   - 支持在线状态联动编辑器：维护 `onlineStatus_link`，支持设备列表选择、新增删除，以及虚拟设备/派生设备跟随真实设备的快捷生成。
12. 配置上传/下载第一版：
   - 配置概览页可填写设备地址、用户、密码、端口和远端 APP 根目录，密码默认 `root`。
   - 上传前会提示用户先自行备份设备内配置，并在确认后清空远端对应配置目录再上传当前工作区配置。
   - 下载时选择本地目录，批量拉取远端配置并自动重新导入为当前工作区。
   - 优先使用 `plink/pscp -pw` 支持密码登录；未安装 PuTTY 工具时回退到系统 `ssh/scp`，适合 SSH key 场景。
   - 上传/下载过程中显示阶段进度和正在处理的文件名；本地解包按 UTF-8 解释 tar 文件名，避免中文文件名乱码。

## 2026-06-05 派生设备讨论与实现记录

已实现第一版“派生设备”批量映射入口：

- 在“计算点”页的模板生成区域新增“派生设备”按钮。
- 弹出“派生设备批量生成”向导，支持选择源真实设备、目标模型、源点前缀到目标 DeviceId 的实例表。
- 支持从源设备点表自动识别前缀，例如 `Inv1_`、`Inv2_`、`Inv3_`。
- 预览 `源设备#源点 -> 目标设备#目标点`，状态区分“新增”“更新”“目标模型无点”“目标设备不存在”。
- 生成时批量 upsert `computation_points`，默认公式 `{1}`、`drop_operands=true`。
- 可选自动创建缺失目标设备，可选自动生成在线联动 `派生设备 -> 源真实设备`。
- 构建验证：新增源码已编译通过，最终链接因本机已有 `CEPB_ControlCenter.exe` 进程运行导致 exe 覆盖失败。

用户试用后的新判断：

- 当前“手动选择源设备、目标模型、前缀实例”的向导虽然可用，但对普通配置人员仍偏抽象。
- 更符合配置人员直觉的流程，可能不应从 LogicCenter 的“计算点/派生向导”出发，而应从 104 设备配置本身出发。
- 暂定前提：一个设备内承载大量点位并拆出多个虚拟设备的场景，当前只考虑 104 协议；Modbus 和后续 DLT645 暂不纳入派生虚拟设备流程。
- 新方向：如果多台 104 设备的 IP、端口、公共地址完全一致，工具可认为它们来自同一台实际南向设备。
- 在保存/导出时，选择其中一台作为实际主设备，其余设备作为虚拟设备：
  - 主设备导出到南向 104 配置。
  - 虚拟设备不作为独立南向采集设备导出。
  - 虚拟设备点位按统一前缀写入主设备模型/点表，例如以虚拟设备 DeviceId 作为前缀。
  - 自动生成虚拟设备点位到主设备前缀点位的 `computation_points` 映射。
  - 自动生成在线联动，让虚拟设备在线状态跟随主设备。
  - 虚拟设备北向可见性应能设为不可见，即不进入 northmodel 生成。

待讨论重点：

- “主设备”的选择规则：自动选择最小 DeviceId、第一台、或由用户显式指定。
- 虚拟设备点位前缀规则：默认 DeviceId，例如 `1_Ua`，或允许自定义 `Inv1_`。
- 是否真的修改主设备模型，还是只在导出阶段生成一个临时聚合模型，避免污染用户原始模型。
- 虚拟设备“北向不可见”字段应放在设备扩展属性、导出策略，还是单独的可见性配置中。
- 现有第一版派生向导是否保留为高级工具，还是改造成从“104 同通道设备组”页面进入。

## 2026-06-05 同通道派生第一版落地

已按“104 同通道设备组”方向完成第一版实现：

- 导出前自动扫描 104 设备，按 `IP + port + 公共地址(addr)` 分组。
- 同组设备数量大于 1 时，默认选择模型点位数量最多的设备作为主设备。
- 其余设备作为附属/派生设备处理。
- 对每个附属设备有地址绑定且非控制类的点：
  - 在主设备模型中生成镜像点，DOname 规则为 `附属DeviceId_原DOname`，例如 `1_Ua`、`2_P`。
  - 镜像点 `northVisible=false`，因此会写入主设备原始 model，但不会进入 northmodel。
  - 镜像点写入 `extensions.generatedBy=iec104SameChannelDerivedDevice` 等元数据，用于标记自动生成、来源设备和来源点。
  - 主设备绑定表同步生成对应绑定，地址沿用附属设备原 104 地址。
  - LogicCenter 自动 upsert `computation_points`，把主设备镜像点映射到附属设备原点。
  - 自动生成 `onlineStatus_link`，让附属设备在线状态跟随主设备。
- 模型点编辑器新增“显示自动派生点”勾选项，默认不勾选；自动派生点默认隐藏，用户主动勾选后才显示。
- 模型文件导入/导出已支持保存点级 `northVisible=false` 和 `extensions`，以便自动派生标记落盘后可读回。
- 构建验证通过：`D:\QT\Tools\Ninja\ninja.exe -C build`。

后续仍需确认：

- 附属设备在 104 南向 `dev` 目录中的最终导出策略。当前第一版先完成自动补点与 LogicCenter 映射，尚未强制从 104 dev 导出中移除附属设备，避免丢失用户按设备维护的配置源信息。后续需要结合运行侧确认是保留 dev、导出空 dev、还是另设虚拟设备持久化字段。
## 2026-06-06 同通道附属设备 dev 导出策略确认

附属设备在 104 `dev` 目录中仍然需要导出设备文件，但导出内容应作为“空南向设备壳”：

- 保留 `DeviceDesc`。
- 保留 `DeviceId`。
- 保留 `Model`。
- `addr` 输出为空字符串。
- `ipa` 输出为空字符串。
- `port` 输出为空字符串。
- `meas_points` 输出空数组。

实现已完成：`serializeDevice()` 检测到设备扩展属性 `derivedIec104Virtual=true` 时，按上述规则导出。这样附属设备身份和北向模型关系仍然存在，但不会作为独立 104 南向采集连接，也不会导出测点。

构建验证通过：`D:\QT\Tools\Ninja\ninja.exe -C build`。

## 2026-06-07 104 同通道派生方案回退

重新评估后，104 同 IP、端口、公共地址下拆分多个逻辑设备的能力不再放在配置工具和 LogicCenter 计算点里实现，改由南向 104APP 承担。

配置工具侧调整：

- 移除“计算点”页里的“派生设备”批量生成入口。
- 移除“在线联动”页里的“派生设备跟随真实设备”快捷按钮，仅保留通用在线联动表和“虚拟设备跟随真实设备”能力。
- 保存/导出时不再自动扫描 104 同通道设备组。
- 不再自动选择主设备/附属设备。
- 不再自动生成主设备镜像点、点级 `extensions.generatedBy=iec104SameChannelDerivedDevice`、`computation_points` 或 `onlineStatus_link`。
- 不再把附属设备按空 `addr/ipa/port/meas_points` 导出；所有 104 设备均按用户配置的正常设备导出，保留自己的 `DeviceId`、`Model`、`ipa`、`port`、`addr` 和 `meas_points`。
- 模型点编辑器移除“显示自动派生点”开关。

新的职责边界：

- 配置工具只负责让用户正常配置多个 104 模型和设备。
- 多个 104 设备可以拥有相同 `ipa + port + addr`，但它们之间的 IOA 应保持唯一。
- 后续配置工具可增加“同通道 104 设备之间 IOA 唯一性检查”，仅做校验提示，不做自动改写。
- 104APP 后续应负责识别/承载同一物理 104 通道下的多个逻辑设备：只建立一条物理连接，并按 IOA 将数据分发到对应逻辑 `DeviceId#DataRef`。

构建验证通过：`D:\QT\Tools\Ninja\ninja.exe -C build`。
